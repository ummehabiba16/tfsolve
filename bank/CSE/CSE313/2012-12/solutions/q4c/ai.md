If every process is asleep, the CPU is idle (the kernel runs the idle loop), but **interrupts are still enabled**. A process can be woken only by an **asynchronous event** that is handled by the kernel, not by another process:

1. **Device interrupt (I/O completion):** e.g. the disk controller signals that the block a process slept on has arrived; the **interrupt handler** (disk driver) marks the buffer valid and calls `wakeup(buffer address)`.
2. **Clock (timer) interrupt:** a process sleeping for a timed event (`sleep(n)`, an alarm) is woken by the clock handler when the time expires (`wakeup` for the event).
3. **Terminal/network input:** a keyboard or network interrupt handler wakes the process waiting for the data.
4. **Signals** (e.g. generated by the terminal driver or timer): a process sleeping at an *interruptible* priority is woken so that it can handle the signal.

`wakeup` removes the process from the sleep hash queue, sets its state to **ready to run** and puts it on the run queue; the handler returns, the scheduler (idle loop) finds a ready process and **dispatches it**: it moves from *asleep* $\to$ *ready* $\to$ *running*.
