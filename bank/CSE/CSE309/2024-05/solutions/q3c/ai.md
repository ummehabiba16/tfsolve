"LL(1)" means: scan the input **L**eft to right, produce a **L**eftmost derivation, use **1** symbol of lookahead.

**Why leftmost:**

1. The parser builds the parse tree **top-down** while reading the input **left to right**. The next input symbol to be matched is the leftmost unmatched terminal of the sentence.
2. In a sentential form $wA\beta$ ($w$ = terminals already matched), the symbols that produce the next input come from the **leftmost nonterminal** $A$. Expanding any nonterminal to the right of $A$ would not help match the next input symbol, and the parser would have no lookahead information to choose its production.
3. So at each step the parser expands the leftmost nonterminal, choosing the production with $M[A, a]$, where $a$ is the lookahead.

**Invariant of the table-driven parser:** (matched input) + (stack contents, top to bottom) is always a **left-sentential form**:

$$S \underset{lm}{\overset{*}{\Rightarrow}} w\alpha$$

Each `output A -> X1...Xk` step (pop $A$, push $X_k \ldots X_1$) is one step of the leftmost derivation, and the outputs in order are exactly the leftmost derivation.

**Example** ($E \to TE'$, $E' \to +TE' \mid \epsilon$, $T \to \textbf{id}$, input `id + id`):

$$E \underset{lm}{\Rightarrow} TE' \underset{lm}{\Rightarrow} \textbf{id}\,E' \underset{lm}{\Rightarrow} \textbf{id} + TE' \underset{lm}{\Rightarrow} \textbf{id} + \textbf{id}\,E' \underset{lm}{\Rightarrow} \textbf{id} + \textbf{id}$$

These are exactly the productions the LL(1) parser outputs, in the same order.
