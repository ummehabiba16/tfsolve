When lexical analysis and parsing are separate, they communicate only through a **stream of tokens** (`<token-name, attribute>`). That clean interface makes it easier to adapt an existing compiler to a new language:

1. **Lexical differences need only a new lexer.** If the new language has the same structure but different spelling (different keywords, e.g. `begin`/`end` vs `{`/`}`, keywords in another natural language, different number or string formats, comment syntax, character encoding), only the lexer is rewritten. The parser still receives the same tokens, so it and the rest of the compiler are reused.
2. **Syntactic differences need only a new grammar.** If the tokens are the same but the syntax differs, the lexer is reused and only the parser changes.
3. **Generators make both cheap.** The lexer is described by regular expressions (Lex) and the parser by a grammar (Yacc), so each can be regenerated independently from a short specification.
4. **Portability.** Input-device and character-set details stay in the lexer, so moving the language to another environment again touches only the lexer.

Without the separation, every change in spelling would be spread through the grammar (white space, comments and character-level rules), and the whole parser would have to be rewritten.
