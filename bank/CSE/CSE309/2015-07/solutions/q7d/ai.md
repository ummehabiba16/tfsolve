**Yacc** is a parser generator: from a specification of a grammar with semantic actions it produces an LALR parser written in C (Dragon book sec. 4.9.1). To construct a translator (for example an infix-expression evaluator):

1. **Write the Yacc specification** `translate.y`, which has three parts separated by `%%`:

   - *Declarations:* C declarations between `%{` and `%}` (includes, globals), the grammar's **tokens** (`%token DIGIT`), operator precedences (`%left '+'`), and the types of attribute values.
   - *Translation rules:* each grammar production followed by a **semantic action** in braces; the value of the head is written with two dollar signs and the values of the body symbols are `$1`, `$2`, ... .
   - *Supporting C routines:* the lexical analyzer `yylex()` (written by hand or generated by Lex), `yyerror()` and `main()`.

2. **Run Yacc:** `yacc translate.y` produces the C program `y.tab.c`, containing the parsing table and the parser `yyparse()` (`yacc -d` also writes `y.tab.h` with the token codes).
3. **Compile:** `cc y.tab.c -ly` (plus `lex.yy.c` and `-ll` if the lexer was produced by Lex) gives the translator `a.out`.
4. **Run** `a.out` on the input; `yyparse()` calls `yylex()` to get tokens, parses and executes the semantic actions as it reduces, which produce the translation.

```text
translate.y --yacc--> y.tab.c --cc (+ lex.yy.c, -ly -ll)--> a.out : input --> output
```

**Example (desk calculator):**

```c
%{
#include <ctype.h>
#include <stdio.h>
%}
%token DIGIT
%%
line   : expr '\n'         { printf("%d\n", $1); } ;
expr   : expr '+' term     { $$ = $1 + $3; }
       | term ;
term   : term '*' factor   { $$ = $1 * $3; }
       | factor ;
factor : '(' expr ')'      { $$ = $2; }
       | DIGIT ;
%%
int yylex(void) {
    int c = getchar();
    if (isdigit(c)) { yylval = c - '0'; return DIGIT; }
    return c;
}
```

*Check:* this specification was compiled with `bison` and run: `2+3*4` gives 14, `(2+3)*4` gives 20, `9*9+9` gives 90.
