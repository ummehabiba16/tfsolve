**Default behaviour.** When an interrupt is accepted, the ATmega32 pushes the PC and **clears the global interrupt enable bit (I-bit in SREG)** in hardware. So while an ISR runs, no other interrupt can be served: nested interrupts are **disabled by default**. The `RETI` at the end of the ISR (generated by the compiler) sets the I-bit again.

**Procedure to enable nested interrupts**

1. Configure and enable the individual interrupts as usual (e.g. MCUCR/GICR for INT0/INT1, TIMSK for timers) and call `sei()` in `main()`.
2. **Inside the ISR that may be interrupted, set the I-bit again** with `sei()` as the first statement (after anything that must not be interrupted, e.g. clearing the source):

   ```c
   ISR(INT0_vect)
   {
       sei();            // re-enable global interrupts: other ISRs can now nest here
       /* ... long work ... */
   }                     // RETI on exit
   ```

   Equivalently, avr-gcc's `ISR(INT0_vect, ISR_NOBLOCK)` inserts the `sei` automatically.
3. Any pending enabled interrupt can now interrupt this ISR; its own ISR runs and returns with `RETI`, then the first ISR continues.

**Cautions:** keep stack space for the deeper nesting; for a level-triggered source, clear or disable the source before `sei()`, otherwise the same interrupt re-enters immediately; protect shared data (`volatile`, `cli()`/`sei()` around multi-byte accesses).
